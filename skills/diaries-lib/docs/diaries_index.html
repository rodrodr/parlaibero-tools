Pipeline de Diarios Parlamentarios · ParlaIbero

diaries-*

21 skills nativos de Claude Code que transforman diarios de sesiones parlamentarias —PDF escaneado o digital, HTML, XML, DOCX o texto plano— en matrices estandarizadas de intervenciones. Desde el OCR hasta el esquema canónico final, con un sistema de confianza de tres niveles que mantiene al investigador en control de cada decisión automática.

Sistema de confianza

AUTO · FLAG · HALT

● AUTO
≥ 0.85
umbral por defecto · ajustable por skill

El skill completó la tarea con alta confianza. El pipeline continúa automáticamente al siguiente paso sin ninguna intervención.

Sin acción requerida
◐ FLAG
≥ 0.65
umbral por defecto · ajustable por skill

El resultado es válido pero hay incertidumbre. El pipeline continúa y el caso se registra para revisión posterior en /diaries-review.

Revisar con /diaries-review
✕ HALT
< 0.65
umbral por defecto · ajustable por skill

La confianza es insuficiente para continuar o se produjo un error. El pipeline se detiene y se requiere intervención manual inmediata.

Intervención manual obligatoria
Fórmulas de confianza por skill
/diaries-ocr 0.7 × media_páginas + 0.3 × página_mínima
/diaries-tag  ⚠ 0.80/0.60 n_auto / (n_auto + n_sin_tag + n_llm × (1 − conf_llm))
/diaries-correct integridad: 0.95 si out_chars ≥ 0.80 × in_chars (si no, 0.60 → FLAG)
/diaries-match  ⚠ 0.90/0.70 n_vinculados_auto / n_oradores_únicos
/diaries-meta campos_extraídos / 5
/diaries-standardize 1 − (errores_validación / n_filas)
/diaries-matrix 1 − (bloques_sin_orador / bloques_totales)
/diaries-document 1.0 (determinista, sin LLM)

Las CINCO clases de marcador · semilla por país
FORMAL (la única que abre turno) · APARTE (queda en el texto del anfitrión) · MENCIÓN (se ignora) · VOTO nominal (tag.vote_patterns → dm_speech = 0) · NARRATIVA (tagging_style: narrative — DO/CO: el orador va en una cláusula en prosa). Semilla del descubrimiento: docs/_metodologia/FASE_C_MARCADORES_POR_PAIS.md. Terminadores verificados: ES·GT·EC «:» · UY «.—» · EC también «.-» (grafía OCR) · PT «—» solo. Tolerancia OCR obligatoria: la ñ rota (seflor, sefior, senor…) · EL→FL · H.D.→HE.
⚠ Prerequisito · el corpus debe estar YA deduplicado
/diaries-meta → /diaries-dedupe → /diaries-tag El Paso 0c rankea las formas de marcador por frecuencia sobre TODO el corpus para decidir cuáles entran al léxico. Con sesiones duplicadas dentro, sus formas se cuentan dos veces y la calibración sale sesgada. Deduplicar después NO lo arregla: la decisión ya se tomó sobre datos inflados.

Gates de la matriz
Entrada: ABORTA si alguna sesión de diaries-tag está en HALT por falsos negativos. Incrustados (marcador absorbido en el text de otra fila): ratio ≤ 0,1% → aceptable, split_embedded_markers.py divide el residuo; > 0,1% → NO se parchea el CSV: se corrige la capa de origen y se re-corre correct → tag → matrix. Prolegomena: todo lo anterior al primer marcador entra como fila con intervention_order = 0 y dm_speech = 0, sin desplazar la numeración (recover_frontmatter.py). Sin tope de longitud. ANEXOS del diario: dm_speech = 0 SOLO donde el acta marca separador explícito (matrix.annex_separator); sin marca no se especula. Default: dm_speech = 1 — el 0 solo donde está demostrado.

Paso 3-bis · Atribución de la presidencia por TRAMO (president_meta)
Muchas cámaras etiquetan a quien preside solo con el cargo (PRESIDENTE, PRESIDENTA, O SR. PRESIDENTE), sin nombre. Sin este paso esas filas se quedan sin id_dep para siempre: PE 42,1% · DO 36,5% del corpus. Se ejecuta con attribute_presidency.py (--apply / --check), parametrizado en country_config (presidency: scope session|segments · sources · target_exclude · back_to_base) — NO se escribe un script por país. El modo por tramos sigue los relevos que el propio acta declara (meta los registra en presidency.segments): un solo presidente por sesión falla el 35,0% de los casos (UY, medido). Marca match_method = "president_meta" para que el origen quede auditable. ⚠ REGLA DE PARADA — no inventes cuando hay varias presidencias: 1 sola presidencia .................. atribuye varias, distinto sexo ............... desempata con PRESIDENTE/PRESIDENTA contra el sexo del padrón conviven titular y «en funciones», o 2+ del mismo sexo ................. NO atribuyas — el acta nombra a quienes presidieron, pero no dice cuándo se produjo el relevo
Paso 3d · Consistencia temporal (obligatoria)
fecha_inicio ≤ date ≤ fecha_fin para toda fila con id_dep referencias: DO 99,96% · PE 97,40% < 99% → FLAG
Paso 3-ter · Integridad referencial matriz ↔ padrón (Gate E)
Todo id_dep del enriched debe existir en deputies.csv, y todo par (id_dep, legislatura) debe existir en el padrón. Se comprueba ANTES de standardize. id_dep inexistente → error duro: se corrige, no pasa al canónico. Par huérfano → la fila NUNCA se elimina (primacía del diario): se completa el padrón o se declara en process_report.md como medida de completitud.

⚠ Seguridad de reejecución · qué destruye un --force
El guardia protege el archivo, pero NO avisa de lo que se pierde. Siempre disponibles

Comandos de control

/diaries-status

Muestra el estado del pipeline en tabla: los 13 skills en su orden canónico (bootstrap → ocr → extract → correct → meta → dedupe → tag → matrix → deputies → match → merge → standardize → document) × niveles (completo / flag / halt / pendiente). dedupe se cuenta POR SESIÓN.

/diaries-status --country {iso2}
/diaries-review

Revisión interactiva de casos FLAG y HALT. Para cada FLAG: evidencia, confianza y decisión [A]ceptar · [C]orregir · [E]scalar · [S]altar. Los HALT se listan con su error y se marcan resueltos tras la intervención manual.

/diaries-review --country {iso2}
/diaries-feedback

Inyecta una corrección en el estado. Tres tipos: punctual (1 sesión), rule (desde fecha → re-procesa), strategy (todo el skill + --force).

/diaries-feedback --country {iso2} --skill diaries-tag \
  --type rule \
  --description "Nuevo patrón de orador" \
  --pattern "^EL SR\." --action "tag_as_speaker" \
  --from 1931-09-01
/diaries-report

Genera el informe completo del proceso: línea temporal, distribuciones de confianza, historial de correcciones y tasa de automatización.

/diaries-report --country {iso2}
# Salida: docs/{iso2}/process_report.md
/diaries-decide

Registra una decisión metodológica en el momento, con su evidencia. Capturar e informar son cosas distintas: lo que no se captura cuando se decide, se pierde. La evidencia es obligatoria y se valida — existe para impedir que se registre una preferencia como si fuera un hallazgo. Las decisiones superadas no se borran: se marcan y se enlazan desde la que las anula, y esa cadena es el historial de correcciones del corpus.

/diaries-decide   # modo interactivo

# consultar lo registrado
python3 ~/.claude/skills/diaries-lib/lib/utils/record_decision.py \
  --pais {iso2} --listar

# regenerar el documento metodológico
python3 scripts/generar_metodologia.py
# Salida: docs/_metodologia/generados/METODOLOGIA.md
/diaries-validate

Valida la integridad estructural del corpus por muestreo, con auto-filtro PASS/FLAG y calibración empírica de la tasa de fuga. Produce la cifra de calidad que el corpus puede afirmar, no la que se supone.

/diaries-validate --country {iso2}
/diaries-teach

Guía interactiva del sistema. Ofrece 8 caminos: visión general, nuevo país, retomar pipeline, problemas por skill, sistema AUTO/FLAG/HALT, correcciones, mapa completo y registro de decisiones metodológicas.

/diaries-teach
/diaries-refine

Mejora un skill a partir de una observación de testing real. Edita el SKILL.md en el repositorio, sincroniza a ~/.claude/skills/ y registra el cambio en REFINEMENTS.md.

/diaries-refine --skill diaries-tag \
  --issue "Los patrones multi-línea no se detectan"

/diaries-refine   # modo interactivo

Instalación

git clone <repo-url> diaries
2 Ejecutar el instalador

Un único script instala las dependencias Python, verifica que los 21 skills estén en ~/.claude/skills/ y crea la estructura de directorios.

cd diaries
bash install.sh
3 Empezar

Abre Claude Code desde el directorio del repositorio y ejecuta la guía interactiva.

/diaries-teach

Skills · fuente única

Los 21 SKILL.md son la fuente única en ~/.claude/skills/diaries-*/ (versionada con git ahí, disponible a cualquier harness). No hay copia en el repo. Se editan directamente allí — p.ej. con /diaries-refine, cuyo cambio queda activo de inmediato y se registra en REFINEMENTS.md. No hay que copiar ni sincronizar.

Ollama · OCR local

Necesario solo para PDFs escaneados (pdf_image). El instalador avisa si falta.

ollama pull Maternion/LightOnOCR-2:1b  # primario
ollama pull glm-ocr                    # fallback por defecto (por país)
Estructura de directorios generada automáticamente

Al ejecutar /diaries-bootstrap por primera vez para un país, se crean todos los subdirectorios necesarios:

source/{iso2}/
├── raw/                  ← fuentes originales (tú las colocas)
├── ocr/{session_id}/     ← páginas OCR por sesión
├── extracted/            ← texto FIEL (conserva ---PAGE N---)
├── corrected/            ← párrafos corregidos
├── tagged/               ← texto con <int> tags
├── meta/                 ← JSON de metadatos
├── matrix/               ← interventions_raw.csv (acumulativo)
├── deputies/             ← deputies.csv
├── match/                ← matching_table.csv
├── merge/                ← interventions_enriched.csv
└── standardize/          ← {ISO2}_interventions.csv (canónico ⚠)
                            + {ISO2}_deputies.csv (padrón publicable)

docs/{iso2}/
├── README.md          ← documentación principal del corpus
├── data_dictionary.md ← diccionario de variables
├── dataset.jsonld     ← metadatos Schema.org (CC BY 4.0)
├── corpus_info.json   ← respuestas del procesador (reutilizable)
└── process_report.md  ← informe del proceso

El directorio docs/{iso2}/ es independiente de source/{iso2}/: la documentación de cada corpus nacional es un activo propio, separado de los datos de trabajo.
