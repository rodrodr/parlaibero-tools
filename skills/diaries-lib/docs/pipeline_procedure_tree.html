Árbol de procedimiento del pipeline ParlaIbero

Cada skill diaries-* con sus opciones de invocación, prerequisitos, condiciones de decisión y la acción que toma según cada rama. El hilo conductor es la puntuación de confianza, que cada skill convierte en estado del pipeline.

AUTO · complete FLAG · revisar HALT · detener SKIP · no aplica TEST / decisión artefacto E/S ERROR · aborta

Claude es el orquestador: lee cada SKILL.md, ejecuta las utilidades deterministas de lib/utils/, y resuelve con su juicio los casos ambiguos. Todos los skills de sesión aceptan --session · --batch · --all + --force · --dry-run.

El modelo de confianza — hilo conductor de todo el pipeline

Skills del pipeline — detalle de decisiones

0 diaries-bootstrap
Configura el país: audita lo ya hecho, infiere config, entrevista, inicializa estado nivel paíssolo --country
Paso 0 · Test de material fuente
¿Existe y no está vacío source/{iso2}/raw/?
vacío / no existe→ERRORaborta: «copia los archivos fuente antes de ejecutar»
hay archivos→lista session_ids (stem de cada archivo) y continúa
Paso 0b · Inventario de trabajo previo (por sesión y por país)
Para cada sesión comprueba qué etapas ya tienen output → celda OK / SKIP / . (pendiente). Clasifica:
ninguna etapa→sesión virgen → pending
algunas etapas con output→marca esas complete (detectado), resto pending
ocr/ vacío + formato digital/html→SKIP OCR (normal y correcto)
ya existe pipeline_state.json→NO sobreescribe: fusiona sesiones nuevas y actualiza pendientes detectadas
Paso 1 · Inferencia automática del formato (discriminador FIABLE)
¿Los archivos de análisis son raw o ya procesados?
corrected/ o extracted/→infiere formato del contenido o pregunta (confianza 0.70/1.0)
raw/ → assess_source.py→estructura por año (capa de imagen vía pdfimages), NO char-count
año DIGITAL→pdf_digital → texto embebido, OMITIR OCR
año ESCANEADO/MIXTO→pdf_image → capa OCR de calidad desconocida (ante duda: OCR)
⚠ Paso 1d — chequeo de integridad del prefijo de orador en escaneados: si garble_ratio > 0.40 con corrupción real (p.ej. SEROR≈SEÑOR) → source_format: pdf_poor_ocr, OCR obligatorio. (UY 1987: embebido detectó 14 intervenciones, OCR 164.)
Paso 2 · Entrevista dirigida
campo confianza < 0.80→muestra evidencia y pregunta (máx 8 preguntas)
usuario confirma regex→úsalo directo (confianza 1.0)
usuario dice «no sé»→deja needs_review: true
ya hay sesiones tagged→toma sus patrones como referencia y reduce la entrevista
Salidas
country_config/{iso2}.yaml state/{iso2}/pipeline_state.json docs/{iso2}/onboarding_report.md
1 diaries-ocr
OCR con Ollama (LightOnOCR-2:1b → glm-ocr) sobre escaneados nivel sesión0.85 / 0.65
Opciones
--session YYYY-MM-DD--batch YYYY-MM --all--force--dry-run
Paso 0 · Test de formato (puerta de entrada)
¿source_format requiere OCR?
pdf_digital / html→SKIP imprime aviso, NO toca estado, deriva a extract
pdf_image / pdf_poor_ocr→arranca Ollama (mata huérfanos, KEEP_ALIVE=-1) y procesa
Paso 1 · Filtro de pendientes
status complete o skipped→excluida (salvo --force)
--dry-run→imprime comando, no ejecuta ni actualiza
Paso 2d · Confianza y estado
confidence = mean_confidence (del OCR) páginas en low_confidence_pages < 0.50 → advertencia en el resumen
AUTOconfidence ≥ 0.85
FLAG0.65 ≤ confidence < 0.85
HALTconfidence < 0.65
Rendimiento: el GPU satura con 1 inferencia → workers = ollama_num_parallel = 6 es el óptimo; 8 perjudica. Causa #1 de lentitud = procesos huérfanos (matar antes del batch). Paralelizar a nivel de página.
Salida
source/{iso2}/ocr/{id}/page_*.txt
2 diaries-extract
Texto limpio + eliminación de cabeceros/pies recurrentes nivel sesión0.85 / 0.65
Paso 3b/3c · Mapeo source_format → modo de extracción
pdf_digital→pdf_digital — páginas vía fitz (paginado)
pdf_image / pdf_poor_ocr→ocr_pages — lee los page_*.txt ya producidos · NO reprocesa OCR
html→html — 1 «página», sin strip
text_flat→text_flat — texto ya extraído sin paginar
Eliminación de cabeceros/pies (page-aware o texto plano)
paginado (PDF / page_*.txt)→detector por recurrencia en zona-borde de cada página (cluster difuso + ancla de pie)
text_flat + page_break_marker→segmenta por marcador y usa el detector paginado
text_flat sin marcador→modo frecuencia: excluye turnos de orador y prosa en caja de oración
Paso 3e/3f · Confianza, integridad y estado
confidence = valid_ratio si chars(salida) < 500 → confidence = min(confidence, 0.60) si pdf_poor_ocr y garble_ratio>0.50 → confidence = min(confidence, 0.55) (prefijo de orador corrupto) si header_suspect_count > 0 → FLAG (posible falso positivo del stripper) si header_removal_ratio > 0.25 → FLAG (posible sobre-detección)
AUTO≥ 0.85 y sin alertas
FLAG0.65–0.85 · o alerta de cabeceros
HALT< 0.65 · prefijo OCR corrupto
Salida
source/{iso2}/extracted/{id}.txt
3 diaries-correct
Corrección tipográfica: párrafos, hifenación, normalización por país nivel sesión0.85 / 0.65
Paso 2c/2d · Pase determinista + resolución LLM
correct_text.py: aplica normalize_replacements (regex por país), une guiones de fin de línea, fusiona líneas cortas. Devuelve ambiguous_breaks.
ambiguous_breaks vacío→salta el pase LLM
salto = artefacto (corte de columna/justificación)→une las dos partes con Edit
salto = párrafo real (fin de oración + mayúscula)→no toca nada
Paso 2e · Confianza
ratio_ambiguous = n_ambiguous / total_paragraphs ratio < 0.05 → 0.95 ratio < 0.10 → 0.88 ratio < 0.20 → 0.78 ratio ≥ 0.20 → 0.65 (si corregiste >15% de párrafos como artefactos → −0.05)
Salida
source/{iso2}/corrected/{id}.txt
4 diaries-tag ⚠
Etiqueta oradores — skill crítico, dos niveles de detección 0.80 / 0.60
El honorífico y el terminador son específicos de cada país y cambian por OCR/era/taquígrafo. Paso 0b obligatorio la 1ª vez: analyze_speaker_markers.py descubre variantes/errores antes de tagear.
Paso 2c/2d · Detección de dos niveles + LLM
NIVEL 1 estricto (speaker_tag_patterns)→marcador canónico; guion [-–—] (OCR usa em-dash) → etiqueta directa
NIVEL 2 score ≥ 0.60→etiqueta (recupera ~5% de terminadores irregulares)
NIVEL 2 score ∈ [0.40, 0.60)→caso límite → FLAG / resolución LLM
span sospechoso (untagged)→LLM decide orador (inserta <int speaker>) o lo descarta
Paso 2e · Confianza + guardia estructural
confidence = n_auto / (n_auto + n_untagged + n_llm·(1 − avg_llm_conf)) si n_auto + n_untagged + n_llm == 0 → confidence = 0.50 (sesión sin oradores: sospechosa) GUARDIA (fuente escaneada): si source_format ∈ {pdf_poor_ocr, pdf_image} y chars > 5000 y n_auto < 3 → confidence = min(confidence, 0.50) «prefijo de orador corrompido por OCR embebido → re-OCR obligatorio»
AUTOconfidence ≥ 0.80
FLAG0.60 ≤ confidence < 0.80
HALTconfidence < 0.60
Salida
source/{iso2}/tagged/{id}.txt
5 diaries-meta
Metadatos: fecha, nº de sesión, tipo, legislatura, presidente 0.85 / 0.65
⚠ Paso 0c obligatorio 1ª vez: verificar que los regex están anclados a la fórmula de cabecera de la sesión (no a la 1ª fecha del texto, que suele ser un acta/decreto citado).
Paso 2d · Decisión crítica de date (override del peso)
date_source = text→autoritativa, puede ser AUTO
date_mismatch = true (texto ≠ nombre)→confía en el TEXTO, fuerza FLAG
filename_fallback (texto sin fecha)→nunca AUTO → FLAG obligatorio
missing (ni texto ni nombre)→HALT
Paso 2e · Confianza ponderada (5 campos × 0.20)
cada campo: regex → 0.20 | LLM → 0.17 | no encontrado → 0.0 confidence = Σ contribuciones de {date, session_number, session_type, legislature, president} (el override de date manda sobre el resultado del peso)
Salida
source/{iso2}/meta/{id}.json
6 diaries-matrix
Parse de texto etiquetado → filas CSV (determinista) nivel sesión
Paso 3a/3b · Prerequisitos + auditoría previa
falta tagged/ o meta/→HALT, informa qué falta
n_tags <int> == 0 en fuente→HALT: archivo sin etiquetas válidas
intervention_format→auto · inline (<int speaker>) · standalone (PT)
Paso 3e/3f · Cobertura de tags (salvaguarda anti-bug del parser)
tasa_cobertura = (interventions_added + filtered_short) / n_tags_fuente confianza = 1 − untagged_blocks / (interventions_added + untagged_blocks) si tasa_cobertura < 0.80 → confianza = min(confianza, tasa_cobertura)
completeconfianza ≥ 0.80
FLAGconfianza < 0.80 · o cobertura < 0.50
HALTcobertura < 0.20 (fallo sistemático)
Salida
source/{iso2}/matrix/interventions_raw.csv (acumulativo)
7 diaries-deputies
Construye la BD de diputados + deduplicación obligatoria nivel país--force · --dry-run
Paso 2 · Guardias
falta interventions_raw.csv→ERROR ejecuta diaries-matrix
deputies.csv existe y no --force→ERROR usa --force
Paso 3/4 · Dos rutas de construcción
deputies.external_file definido→Ruta A: valida columnas, genera id_dep si falta, mapea a esquema canónico
external_file vacío→Ruta B: extrae speakers únicos, agrupa por similaridad (clúster 4+ → juicio LLM)
Paso 5 · Deduplicación (SIEMPRE, 3 pasadas)
Pasada 1: fuzzy token_sort_ratio ≥ 85→typos, acentos, OCR, orden de tokens
Pasada 2: subconjunto de apellido + mismo nombre→apellido completo vs primero (inter-legislatura)
Pasada 3: vecinos ±5 ordenados por apellido→iniciales expandidas (Alfonso G. ↔ Alfonso González)
par ambiguo→presenta al usuario (partido/distrito/fechas) antes de fusionar
Mismas filas con mismo id_dep en distintas legislaturas son correctas. Re-escanea tras cada ronda de fusión.
Paso 6 · Confianza
confianza = 1 − clustered_ambiguous / total_unique ( < 0.85 → FLAG )
Salida
source/{iso2}/deputies/deputies.csv
8 diaries-match
Vincula speaker_raw → id_dep (umbrales altos) nivel país0.90 / 0.70
Cascada de métodos de vinculación
Paso 4 · fuzzy_match.py: limpia títulos, matchea contra nombre completo Y apellidos (token_set_ratio), filtra por vigencia temporal (mandato vs fecha de sesión).
match_method = exact→vinculado
= fuzzy (≥ threshold)→vinculado
= ambiguous (apellido compartido)→trae candidates → LLM elige por contexto
= unmatched→Paso 4b heurísticas estructurales (prefijo, iniciales, apellido+nombre) → si no, LLM
Paso 5 · LLM resuelve ambiguous + unmatched con contexto (±3 intervenciones, partido, fecha) → llm o unmatched final.
Paso 7 · Estado por TASA de cobertura
confianza_global = n_matched_auto(exact|fuzzy, conf≥0.90) / n_unique_speakers sin_resolver = (n_unique − n_matched_auto) / n_unique
completesin_resolver ≤ 10%
FLAGsin_resolver > 10%
HALTsin_resolver > 30%
Salida
source/{iso2}/match/matching_table.csv
9 diaries-merge
Join pandas de raw + matching + deputies nivel país
Paso 3 · Verificación de integridad (crítica)
filas_salida ≠ filas_entrada→HALT: el join perdió/duplicó filas
falta cualquiera de los 3 CSV→ERROR ejecuta el skill que falta
Paso 4 · Estado por match_rate
completematch_rate ≥ 0.90 y filas coinciden
FLAGmatch_rate ≥ 0.70 y filas coinciden
HALTmatch_rate < 0.70 o filas no coinciden
Salida
source/{iso2}/merge/interventions_enriched.csv
10 diaries-standardize
Esquema canónico final (10 columnas) — salida del corpus nivel país
Paso 1 · GUARDIA de sobreescritura (antes que nada)
{ISO2}_interventions.csv existe y NO --force→ERROR aborta. «Sobreescribir elimina el archivo canónico». Nunca continúa sin --force
Paso 5/6 · Validación de esquema → estado por % de error
confianza = 1 − validation_errors / total_rows
completeerrores ≤ 5% de filas
FLAGerrores > 5% de filas
HALTerrores > 20% de filas
session_number acepta entero o alfanumérico (12, 12A, 001O); date debe ser ISO YYYY-MM-DD.
Salida ⚠ canónica
source/{iso2}/standardize/{ISO2}_interventions.csv

Documentación del corpus (entrevista + README canónico) nivel país

existe sin --force→salta entrevista, regenera docs
nuevo→entrevista de 5 preguntas (fuentes, transformación, autores, notas)

Skills de control — disponibles en cualquier momento

Cdiaries-status
Tabla de estado (solo lectura)
Lee pipeline_state.json y agrega por skill: total · OK · FLAG · HALT · Pend · confianza media. Skills país: entrada _country.
hay HALT→«revisa errores y re-ejecuta con --force»
hay FLAG→deriva a /diaries-review
todo complete→«corpus listo» → /diaries-report
solo pending→sugiere el siguiente skill pendiente
Cdiaries-review
Bucle interactivo de resolución de FLAGs --skill (filtro opcional)
Por cada caso FLAG (en orden de pipeline) — menú de opciones
[A] Aceptar→marca complete con la confianza actual
[C] Corregir→registra CorrectionRecord puntual + marca complete
[R] Reintentar MiniMax→solo diaries-ocr: re-OCR de páginas <0.70, recalcula estado
[E] Escalar→marca HALT (intervención manual)
[S] Saltar→mantiene FLAG
[Q] Salir→rompe el bucle
Cdiaries-feedback
Inyecta correcciones — 3 tipos con distinta propagación
Propagación según --type
punctual (--from sesión)→1 sesión · registra CorrectionRecord · no propaga
rule (--from sesión + --pattern/--action)→re-marca como pending todas las sesiones posteriores a --from → re-ejecutar el skill
strategy→añade a global_rules[] · requiere re-ejecutar con --force
Tras editar valida el JSON (json.load); si falla, no confirma el guardado.
Cdiaries-report
Informe del proceso + diagnóstico de salud
Paso 4 · Salud global del pipeline
VERDE→automatización ≥ 80% · sin HALTs · confianza media ≥ 0.85
AMARILLO→automatización ≥ 60% · HALTs ≤ 5% · confianza ≥ 0.75
ROJO→cualquier otra combinación
Incluye histogramas ASCII de confianza por skill e historial de correcciones (punctual/rule/strategy). Salida: docs/{iso2}/process_report.md
Cdiaries-teach
Guía interactiva — 7 caminos
Caminos
1 · qué es el sistema2 · país nuevo desde cero 3 · retomar pipeline4 · problema con un skill 5 · confianza AUTO/FLAG/HALT6 · correcciones y propagación 7 · mapa completo de skills
Cdiaries-refine
Mejora un SKILL.md a partir de testing real
Observación de testing → localiza la sección afectada → propone cambio quirúrgico → [A]plicar / [E]ditar / [C]ancelar → edita el SKILL.md y registra en REFINEMENTS.md.
No modifica datos de sesiones ni el estado. Cambios estructurales grandes → mostrar borrador completo antes de aplicar.
